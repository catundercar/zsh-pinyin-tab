在 zsh 里敲拼音，Tab 补出中文文件名。

中文目录名一直是 Tab 补全的死角：名字敲不出来，Tab 也就无从补起。 这个插件把拼音候选加在原生补全后面——cd wd 补出「文档」， 而原生补全该给的东西一个都不少。

~/notes
$ cd wd

点一下这里，敲拼音，按 Tab 换候选

敲什么，补出什么

首字母、全拼、以及两者的混合都认。演练场里是这些目录。

wd文档每个字取首字母
wendang文档全拼
wend文档前一个字全拼，后一个字首字母——半截也认
xxbj学习笔记四个字的首字母
wdp我的Projects中英混排，连续的英文段当一个整体
mydmy-docs分隔符可跳过
cw / zw重文多音字两个读音都留着

安装

仓库根目录是标准的 zsh-pinyin-tab.plugin.zsh，主流插件管理器加一行就行。 在 compinit 之前或之后加载都可以。

装完 exec zsh 重开一下，随便找个有中文目录的地方敲 cd wd 再按 Tab。 不确定装没装上就跑 zsh tools/doctor.zsh，它不依赖交互式终端， 能把「插件坏了」和「环境不对」分开。

它怎么工作

四层，自底向上。

词表 data/pinyin.zsh

覆盖 CJK 基本区 20892 个字，多音字每字最多留三个读音。由 pypinyin 离线生成，你的机器上不需要 Python。懒加载，而且必须用 zcompile 过的 .zwc——原始 .zsh 解析要 210ms，.zwc 只要 6ms。

索引 _zpt_index

把名字拆成读音序列，我的_Projects 拆成 (wo)(de|di)[_](projects)。连续的英文数字合并成一个 token，分隔符标成可跳过。按名字缓存而不是按路径——「文档」「下载」这类名字在不同地方反复出现，转一次处处受益。

匹配 _zpt_match

是个 DP，不是贪心。反例：输入 wen 配「文档」，w 当首字母走不通（剩下的 en 匹配不上 dang），必须 wen 整体消耗掉「文」才对。每个读音允许消耗它的任意前缀，首字母和全拼就被一条规则覆盖了。

补全集成 _zpt_complete

先跑这个命令原本的补全函数，再把拼音候选加进去。顺序和返回值都有讲究：返回值要如实反映「这一轮到底有没有产出候选」，否则会把用户 matcher-list 里「配不上再忽略大小写」那几轮整个吃掉。

真正跑 DP 的候选很少：先用首字母集合一次 glob 否掉九成以上，再用首字母串和全拼串的前缀命中直接判正，剩下的才进 DP。500 个中文目录下，每次 Tab 中位数 4ms。

它不做什么

写在前面，省得你装完才发现。

  • 不支持乱序和跳字。wgz 不会匹配「我的工作」，必须连续。换来的是候选列表干净，Tab 一下通常就一两个结果。
  • 多段路径只匹配最后一段。cd wd/xm 里的 wd/ 必须是真实存在的路径。想逐段展开那是 zoxide 的活。
  • 有子命令的命令不在默认表里。挂到 git 上，git ch 除了 checkout 还会冒出拼音匹配 ch 的文件——插件分不清这个位置该补子命令还是补文件。
  • 多音字全展开，没有词频排序。「重」（zhong/chong）、「行」（xing/hang）这类字会让候选变多。
  • 只覆盖 CJK 基本区。扩展区生僻字、日文假名当作「可跳过的字符」处理。
